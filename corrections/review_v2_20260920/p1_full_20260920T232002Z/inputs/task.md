# URSS 多 seed 编译稳健性实验 Codex 执行任务

来源：URSS_Multiseed_Experiment_Plan_v1.docx，2026-09-18，v1。

本文件是交给 Codex 的完整任务指令。将本文件放入 URSS 项目根目录，然后要求 Codex 阅读并执行。它包含必要的实验规范，不依赖 Codex 访问此前聊天记录或 Word 文件。以下文件名是预期产物或建议入口，现有项目若有等价机制，应优先扩展并在报告中写明对应关系。

## 任务目标

请在当前 URSS 项目中实现并执行一次有限、预先固定的多 transpiler seed 稳健性实验，完成 P0–P4：核对输入、实现与预检、正式运行、统计审计、生成报告及论文补充。

研究问题是：在冻结的候选表示库、联合预算网格、拓扑和编译设置下，原先观察到的 strict mixed-only 可行区域是否依赖某个编译随机 seed？主要结果是同一个预算点在全部五个测试 seed 下是否仍为 mixed-only。

请实际完成代码修改、必要核验和实验执行，不要仅返回实施建议或空脚本。每个阶段验收完成后继续下一阶段。例行实现选择根据本指令和项目现状自行解决；只有缺失关键输入、无法消除的正确性问题、资源不可用或权限限制真正阻止继续时，才记录阻塞并请求最少量的补充信息。不得绕过工具权限或审批限制。

工作以本地实现、运行、报告和论文源文件修改为范围。保留 Git 状态与可审查 diff；不自动提交、推送、合并、发布到 Overleaf 或向他人发送材料。

3. 优先复用现有实例、候选构建、编译、成本统计和认证机制。本次不重新设计 Hamiltonian、penalty、选择器目标、候选搜索空间或预算网格，也不运行 QAOA 参数优化、采样及无关 E1–E6 全量实验。
4. 所有新增结果写入唯一的 `results/multiseed_<UTC时间戳>/`，或项目等价的独立结果目录。历史原始数据、图表和单 seed 基线保留，不被覆盖。

## 2 冻结实验矩阵

| 维度 | 执行要求 |
|---|---|
| Seeds | `[1729, 2718, 31415, 57721, 65537]`，1729 为对照 |
| 完整样本 | 30 个 Max-3SAT 和 30 个 constructed instances |
| 受限样本 | 同一排序下各 10 个，必须是完整方案的嵌套子集 |
| 拓扑 | 原项目的 line-12、ring-12、grid-12；复用准确边表、方向和物理编号 |
| 候选 | Native、Full 与冻结库内全部 Selective 候选；保留退化 Selective 类别 |
| Synthesis | 原有 canonical 和 reuse，分别统计；合并比较见第 7 节 |
| 其他维度 | 沿用既有层数 p、电路变体、参数和预算维度，逐一写入配置 |

样本选择必须在正式结果生成前完成：

- 冻结每个 family 的合格实例全集、instance_id 与内容 SHA-256。合格性只涉及输入可读、必要数据及已有正确性证据可追溯；不得根据 mixed-only 标签、优势、门数、编译是否成功或容量适配性筛选。
- 对每个实例构造 UTF-8 字符串 `URSS_MULTISEED_V1|{family}|{instance_id}`，替换占位符后计算 SHA-256。使用固定的 family 标识并记入配置，字符串中不加空格或换行。
- 每个 family 内按完整哈希升序排列；哈希相同时按 instance_id 排序。前 30 个为完整方案，前 10 个为受限方案。
- 不足目标数量时保留实际数量、排除原因和缺口；不得临时生成“替补”，也不得把不足规模报告为 30 个。
- 编译资源超限的表示仍保留在任务矩阵与容量统计中。

预检前登记计算预算 `T_cap`。若用户或项目已有明确时限，沿用并注明来源；若未提供，记录为 `null`，表示没有指定时限，默认执行完整方案，不凭空设置时限以缩小样本。只有预检资源估算超过已登记时限时，才自动采用各 10 个实例方案，并记录原因。运行开始后不能根据科学结果更换规模。

完整方案包含 900 个“实例—拓扑—seed”组合，受限方案包含 300 个；计入两种 synthesis 分别为 1800 和 600 个组合。实际编译次数由全部 candidate、p 和电路变体展开的任务清单决定。不要把这些组合数当作编译次数；同一电路的资源可用于整个预算网格。

## 3 冻结编译配置与新旧基线

生成可机器读取的 `experiment_config.yaml`，所有影响比较的“沿用”值必须解析为实际值，并附来源文件或代码位置。至少记录：

- Python、Qiskit 和相关依赖版本、锁文件哈希、OS、CPU、内存及执行环境。
- Git commit、实验相关源代码快照哈希、未提交 patch 和必要的未跟踪源文件哈希；不能只记录不能代表实际工作树的 commit。
- 实例、完整候选库、原始输入电路、精确性证据与预算网格哈希。
- 资源定义、计数口径、单位、预算边界规则；门数究竟统计 CX、全部双比特门还是其他指标，必须明确。
- 层数 p、参数值或符号参数、绑定时机、归一化、penalty、门合并与构造顺序。
- basis gates、optimization level、SABRE heuristic、pass 顺序、相关插件、routing、initial layout 与拓扑边表。
- 五个外部 seed、SABRE 内部 trials、其他随机源、并发度、CPU 限额和单任务超时。

保持 identity placement，并核验实际管线没有额外随机布局搜索。若 `seed_transpiler` 同时改变多个随机 pass，明确将实验称为“编译 seed 稳健性”，不得把变化全部归因为路由。

显式固定原有的有效 SABRE trials，并核实设置确实作用到执行的 pass。不要只在 YAML 中写一个未生效字段。若原值不可追溯，按本计划设为 8，记录配置变化，并在该设置下重新生成 seed 1729 对照。不要假定 `transpile()` 支持未经核验的参数名；读取当前安装版本的 API 或源码，通过项目已有 pass manager 或其合法配置接口落实。

建议单任务超时 300 秒。如预检发现需调整，应在正式执行前调整并重新冻结，所有候选采用相同规则；正式阶段不得只延长有利候选的运行时间。

新 seed 1729 结果应与历史结果比较。存在差异时定位版本、trials、pass、参数或计数原因，保存 `baseline_comparison.csv` 和说明。若采用新的受控编译配置，以新 1729 对照进行五 seed 比较，历史基线单独列出；不能声称相对历史实验“只改了 seed”。若不一致来自未解决的实现错误，不进入正式阶段。

## 4 实现可恢复的运行器

优先扩展现有入口。若不存在等价入口，可新增 `scripts/run_multiseed_robustness.py` 和相应分析入口，提供以下能力：

- 预检或 dry-run：生成具体配置、样本、候选清单与完整任务矩阵。
- pilot：运行第 5 节要求的预检和重复性检查。
- 正式运行：依据冻结 manifest 编译，不在循环中改变候选空间。
- resume：重用已经完整写入且输入、配置与编译实现哈希匹配的任务结果。
- analyze / audit：从保存的原始结果重新生成分类、指标与审计报告，无需重新编译。

任务键至少覆盖 instance_id、candidate_id、拓扑、synthesis、p、电路变体、seed，以及足以区分输入与配置的哈希。重复性检查使用单独的 attempt_id，不产生重复的正式结果行。

保存预期任务清单；采用原子写入或项目已有的可靠方式逐任务落盘。区分编译实现哈希与后处理版本，不能把新增报告导致的工作树变化误当成电路输入变化。

编译记录至少包含任务键、实际 seed、有效 trials、资源向量、耗时、终态、错误原因和电路/日志位置。保持成本字段类型与缺失值语义明确，缺失资源不能填 0。

把两个层面的状态分开：

- 编译终态：`compiled`、`width_exceeded`、`timeout`、`compile_error`；尚未完成的任务另有 `pending` / `running` 状态，不算终态。
- 候选相对于具体 budget_id 的判断：`FEASIBLE`、`INFEASIBLE`、`UNKNOWN`。

同一已编译电路可能在一个预算下可行、在另一个预算下不可行，因此不能把 `infeasible` 作为跨全部预算的唯一编译终态。逻辑宽度超过物理容量可作为该拓扑下的硬排除证据；一般超时或报错只产生未知。不要把未找到编译结果解释为编译不存在。

失败记录保留为终态；重试须在原配置下追加 attempt 并记录原因，不覆盖失败历史。修复影响编译输出的代码后创建新的配置/实现版本，对受影响任务统一失效重跑，不能混用版本。

## 5 P0 与 P1 预检验收

P0 完成仓库检查、样本选择、配置解析、证据核对和任务清单。必要输入缺失时，先实现所有不依赖缺失数据的部分，并输出 `BLOCKERS.md`：缺什么、查过哪些路径、为何影响判断以及准确的恢复步骤。

P1 取两个 family 各自哈希排序首位的一个实例，共两个实例，覆盖三种拓扑、两种 synthesis 和全部候选：

1. 在同一设置下运行 seed 1729 两次，检查资源向量、门数、深度和预算分类一致。
2. 增加 seed 2718；保留预检来源与耗时。
3. 核验资源提取、参数绑定、候选与证据关联、状态处理和恢复机制。数据中若存在可行见证与非 mixed 排除路径，逐项追溯；没有相应实际案例时，不要求预检必须产生 mixed-only，可用明确标注的单元用例验证分类逻辑，但不得将其加入实验数据。
4. 按候选规模、拓扑和 synthesis 的预检耗时估计正式成本，注明只有两个实例的估计局限。登记最终规模、并发及超时设置，再冻结正式配置。

运行现有相关回归；涉及逻辑变换的修改必须通过精确性和电路等价性核验。只补充能验证具体科学风险的测试，至少覆盖：strict mixed 两个条件、UNKNOWN 传播、退化 Selective 的非 mixed 排除、同一电路同时满足全部预算、跨 seed 集合交集及不匹配缓存的拒绝。测试数据与正式实验数据分目录保存。

P1 通过后直接进入 P2。若预检输入、编译实现和配置与正式任务完全一致，可以去重复用第一次有效结果；重复性检查的第二次结果只保留为验证证据。

## 6 P2 正式运行与 mixed-only 判据

执行全部冻结任务，而不是只重新编译原先获胜的 Selected。每个被比较候选使用同一组 seeds 和相同 trials。定期报告真实完成数、剩余数、失败数和基于实测的耗时估计。

strict mixed 候选同时满足：

```text
n_aux > 0
retained_cubic > 0
有效且适用的精确性证据
```

对已完全枚举的实例，关联 `mismatch_count = 0` 和 `inconsistent_minimiser_count = 0` 的真实证据；其他规模使用项目实际支持的证书，并注明范围。字段缺失或证据不适用时不能默认通过。Native、Full 与退化 Selective 都进入非 strict mixed 集合。

某候选在某 seed 和预算下 FEASIBLE，必须由同一个实际编译电路的完整资源向量同时满足全部预算约束。不得把不同 seed、synthesis、候选或参数配置的分量最小值拼接成“更优电路”。

对每个固定的实例、拓扑、synthesis、p、电路变体、seed 与 budget_id，使用三值逻辑：

```text
MIXED_ONLY_TRUE:
  至少一个合格 strict mixed 候选 FEASIBLE，
  且冻结库中所有非 strict mixed 候选均有证据判为 INFEASIBLE。

MIXED_ONLY_FALSE:
  至少一个非 strict mixed 候选 FEASIBLE，
  或所有 strict mixed 候选均有证据判为 INFEASIBLE。

MIXED_ONLY_UNKNOWN:
  剩余无法确定的情况。
```

已有反例足以判 FALSE 时，无需因其他候选缺失而改记 UNKNOWN。已有 mixed 见证且全部非 mixed 已被排除时，其他 mixed 候选未知不妨碍该点为 TRUE。证据失效、候选类别不明或未完成排除时，不能构造肯定认证。

这里的“排除”与“认证”均相对于冻结候选库、所测试编译产物和资源模型。不要外推为所有可能编译方案中的全局不可行。

## 7 P3 统计与图表

按实例、拓扑、synthesis、p 和电路变体固定比较层；先分别报告两个 family 和三种拓扑。

必须生成：

1. **逐 seed 区域**：每个 seed 的 mixed-only 点集合、区域非空实例数，以及 UNKNOWN 数量。
2. **共同预算区域**：五个 seed 的 TRUE 集合交集；报告至少存在一个共同预算点的实例数、明确分母及覆盖率。
3. **基线保留率**：交集点数除以 seed 1729 的 mixed-only 点数。基线为空记 N/A；存在妨碍精确判断的 UNKNOWN 时报告下界与未知，不将其当作已消失。
4. **基线点稳定次数**：对每个基线 mixed-only 点报告五个 seed 的 TRUE / FALSE / UNKNOWN 数，按 1–5 次 TRUE 汇总并保留未知信息。因为包含基线 seed，完整可判定的基线点不会有 0 次 TRUE。
5. **分类翻转**：原有区域在新 seed 下完全消失、部分保留或保持；区分“原预算点丢失”与“新预算点出现”。只有无 TRUE 且无相关 UNKNOWN 时，才确认区域完全消失。
6. **同一候选见证**：在共同区域中，是否存在同一个 strict mixed candidate 在全部五个 seed 下均可行。它与允许随 seed 更换候选的类别稳定性分别报告。
7. **Pareto 稳定性**：在冻结资源维度上重建候选 Pareto 集，并比较各新 seed 与 1729 的 candidate_id 集合 Jaccard 相似度。两集合都为空记 N/A；有缺失导致前沿不完整时显式标注，不能当作完整排名。
8. **Selector 稳定性**：若现有 selector 可用，在每个 seed 下按原目标与 tie-break 重选，记录所选候选；同时检查原 1729 所选候选在新 seed 下的可行性。没有 selector 时记不适用，不另造优化目标。
9. **公平多次编译补充分析**：对所有候选同等合并五个 seed 的实际电路，使用真实资源向量构造 Pareto 前沿后重判预算可行性。与逐 seed 结果分开，不通过分量最小值合成电路。

canonical 与 reuse 先分别统计。若原论文允许在两种 synthesis 之间选择，再对二者实际电路的并集进行同口径比较，不给单一表示额外搜索机会。

先计算每个实例的指标，再汇总 family 和拓扑层面的结果，写明分子、分母、未知与排除原因。不能把预算点、候选、seed、拓扑或 synthesis 当成新的独立实例扩充样本量。此处五个固定 seed 用于描述性敏感性检查，不宣称构成对所有 seeds 的统计保证。

至少输出逐 seed 统计表、共同区域保留图、Pareto 稳定性表。零优势、消失区域与失败覆盖均须呈现；不得只展示成功实例或择优 seeds。

“100% 任务有终态”不等于“100% 成功编译”，更不等于“全部预算点可认证”。存在 timeout 或 UNKNOWN 仍可交付诚实的完整报告，但不能将未知数量隐藏在 PASS 中。mixed-only 消失本身不是实现失败。

在 `EXPERIMENT_REPORT.md` 说明目标、冻结配置、样本和任务量、基线差异、实际结果、失败与覆盖、结论限制和复现命令。不得预设至少 80% 或 90% 保留才通过，也不得在看结果后补一个有利门槛。
